## 项目背景（30秒）

ReviewLens 是电商品牌评论体验分析平台。技术栈：FastAPI + React 18 + PostgreSQL 16 + Elasticsearch 8 + Redis + MinIO。后端在 `backend/`，前端在 `frontend/`，NLP 服务在 `nlp/`。基础设施通过 `docker/docker-compose.yml` 启动（项目分组名 `reviewlens`）。Python/Node 使用本地环境。

## 模块定位

本模块是所有业务模块的基础，提供用户注册、登录、JWT 鉴权和角色控制。所有其他模块的 API 都依赖本模块的 `get_current_user` 依赖注入。

## 依赖关系

- **上游依赖**：无（本模块是基础）

- **下游被依赖**：所有模块（M2-M9）的 API 都需要鉴权

- **前置条件**：Docker Compose 中 PostgreSQL 已启动，数据库已初始化

## 数据库表

```sql
-- users 表
CREATE TABLE users (
    id          UUID PRIMARY KEY DEFAULT gen_random_uuid(),
    email       VARCHAR(255) UNIQUE NOT NULL,
    password_hash VARCHAR(255) NOT NULL,  -- bcrypt
    full_name   VARCHAR(100),
    role        VARCHAR(20) NOT NULL DEFAULT 'operator',  -- admin/analyst/operator
    is_active   BOOLEAN NOT NULL DEFAULT TRUE,
    created_at  TIMESTAMPTZ NOT NULL DEFAULT NOW(),
    updated_at  TIMESTAMPTZ NOT NULL DEFAULT NOW()
);

-- audit_logs 表
CREATE TABLE audit_logs (
    id            UUID PRIMARY KEY DEFAULT gen_random_uuid(),
    user_id       UUID REFERENCES users(id),
    action        VARCHAR(50) NOT NULL,    -- create/update/delete/login
    resource_type VARCHAR(50),            -- dataset/issue/review_task/...
    resource_id   VARCHAR(100),
    details       JSONB,
    ip_address    VARCHAR(45),
    created_at    TIMESTAMPTZ NOT NULL DEFAULT NOW()
);

CREATE INDEX idx_audit_logs_user ON audit_logs(user_id);
CREATE INDEX idx_audit_logs_resource ON audit_logs(resource_type, resource_id);
CREATE INDEX idx_audit_logs_created ON audit_logs(created_at);
```

## API 端点

| 方法    | 路径                        | 说明                               | 鉴权 | 角色    |
| ----- | ------------------------- | -------------------------------- | -- | ----- |
| POST  | `/auth/register`          | 注册（一期开放，生产需管理员邀请）                | 公开 | -     |
| POST  | `/auth/login`             | 登录，返回 JWT access + refresh token | 公开 | -     |
| GET   | `/auth/me`                | 当前用户信息                           | 登录 | -     |
| PUT   | `/auth/me`                | 更新自己的 full\_name                 | 登录 | -     |
| GET   | `/api/v1/users`           | 用户列表                             | 登录 | admin |
| PATCH | `/api/v1/users/{id}/role` | 修改用户角色                           | 登录 | admin |

### 请求/响应示例

```json
// POST /auth/register
// 请求
{ "email": "user@example.com", "password": "Pass123!", "full_name": "张三" }
// 响应 201
{ "code": 0, "data": { "id": "uuid", "email": "user@example.com", "role": "operator" } }

// POST /auth/login
// 请求
{ "email": "user@example.com", "password": "Pass123!" }
// 响应 200
{ "code": 0, "data": { "access_token": "eyJ...", "refresh_token": "eyJ...", "token_type": "bearer", "expires_in": 3600 } }
```

## 技术设计

### JWT 策略

- access\_token：有效期 1 小时，payload 含 `sub`(user\_id)、`role`、`exp`

- refresh\_token：有效期 7 天，仅用于刷新 access\_token

- 密钥从环境变量 `JWT_SECRET_KEY` 注入，缺失时启动报错

- 使用 `python-jose` 签发和验证

### 密码安全

- bcrypt 哈希（rounds=12），使用 `passlib`

- 不存储明文密码，不返回 password\_hash 字段

### 权限控制

```python
# FastAPI 依赖注入示例
async def get_current_user(token: str = Depends(oauth2_scheme), db: AsyncSession = Depends(get_db)) -> User:
    ...

def require_role(*roles: str):
    async def checker(user: User = Depends(get_current_user)) -> User:
        if user.role not in roles:
            raise HTTPException(403, "权限不足")
        return user
    return checker

# 使用
@router.post("/datasets/imports", dependencies=[Depends(require_role("admin", "analyst", "operator"))])
```

## 验收标准

1. 用户可注册、登录、获取 JWT
2. 无效 JWT 返回 401
3. 权限不足返回 403
4. 密码在数据库中是 bcrypt 哈希
5. 所有 API 端点有鉴权保护（除 register 和 login）
6. 单元测试覆盖率 >= 80%
