## 阶段依赖与并行策略

```text
P1 阶段（可并行）:
  窗口1 → M10 部署（Docker Compose + 项目骨架）
  窗口2 → M1 认证（User 模型 + JWT + 鉴权中间件）
  说明：M1 依赖 M10 的项目骨架，但 M1 可在 M10 完成项目结构后启动

P2 阶段（部分并行）:
  窗口1 → M2 数据导入（CSV/JSONL 校验 + ES 同步）
  说明：M2 完成后 M3 和 M4 可并行
  窗口2 → M3 搜索引擎（等 M2 的 ES 索引就绪后开始查询）
  窗口3 → M4 NLP 基线（等 M2 的评论数据就绪后开始推理）

P3 阶段（顺序+并行）:
  先 → M5 审核（等 M4 有预测结果后生成审核任务）
  并行 → M6 训练（等 M5 有 approved 样本后训练）
  并行 → M7 看板（等 M4 预测结果入 ES 后聚合）

P4 阶段（可并行）:
  窗口1 → M8 问题卡
  窗口2 → M9 告警导出

P5 阶段:
  全部模块 → CI/CD + E2E 测试 + 文档
```

## P7 模型增强实验（M11 模块）

> 目标：从"一个基线模型"升级为"完整的模型选型与成本论证实验"。
> 产出面试核心故事：弱标签 vs 蒸馏、基线 vs 微调、成本-精度权衡分析。

### 三层架构设计

```text
第一层（生产）：TF-IDF+LR 基线常驻
  ↳ 小数据低延迟可解释，P6 已完成闭环

第二层（增强）：DistilBERT 微调（6600万参数，CPU 可训练）
  ↳ 样本量敏感性实验：1k / 5k / 2万 / 5万 各训一次
  ↳ 产出"样本量-性能曲线"，确定深度模型收益拐点

第三层（论证）：LLM 蒸馏对照实验（可选，需用户确认 API 成本）
  ↳ 大模型 API 抽样标注 2000-5000 条（高质量软标签）
  ↳ 对比三条路线：A 弱标签基线 / B 纯弱标签微调 / C LLM蒸馏微调
  ↳ 产出成本-精度权衡分析
```
