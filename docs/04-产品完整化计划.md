## 三、P8 前端产品化（核心骨架，最高优先级）

> 目标：让前端从"不可用"变为"结构完整的产品"。完成后新用户可注册→登录→全程操作。

### P8.1 全局布局与导航

**目标**：建立 AppLayout，所有业务页面套在其中。

**实施要点**：
1. 新建 `frontend/src/layouts/AppLayout.tsx`：
   - `antd` `Layout` + `Sider`（左侧菜单，collapsed 可收起）+ `Header` + `Content`

   - 当前选中项高亮跟随路由（`useLocation`）
   - admin 角色追加"用户管理" `/users` 菜单（P9.2 实现页面，菜单可先挂上带权限判断）
2. Header 右侧放用户区（邮箱/角色 Tag + 退出登录下拉，P8.6 完善内容，可先占位）
3. `App.tsx` 改造：业务路由套 `<AppLayout>`（`<Outlet/>` 模式），`/login`、`/register`、404 不套布局
4. **修复 Dashboard#L157 的 `href="#/insights"`**：改为 `<Link to="/insights">` 或 `navigate`
5. Content 区加 `Breadcrumb`（首页/当前页）

**验收**：8 个页面全部出现在侧边栏，点击切换路由正常且高亮正确；Dashboard "排行详情"可跳转 Insights。

### P8.2 登录页与注册页

**目标**：补上系统唯一入口。

**实施要点**：
1. 新建 `frontend/src/api/auth.ts`：
   ```ts
   // register(email, password, full_name) → POST /api/auth/register
   // login(email, password) → POST /api/auth/login，返回 { access_token, refresh_token, expires_in }
   // refresh(refreshToken) → POST /api/auth/refresh
   // getMe() → GET /api/auth/me
   // updateMe(fullName) → PUT /api/auth/me
   ```
   注意统一剥 `{ code, data }` 壳（参考 `api/datasets.ts` 现有写法）。
2. 实现 `pages/Login/index.tsx`（覆盖空文件）：
   - antd `Form`（邮箱+密码，必填校验+邮箱格式校验）
   - 调 `auth.login`，成功后 `setToken(access_token)` + refresh_token 存 `localStorage`（新 key `reviewlens_refresh_token`，client.ts 加 `getRefreshToken/setRefreshToken`）
   - 成功后 `navigate(from || '/dashboard')`（支持 location state 记录来源页）
   - 已登录访问 /login 自动跳 /dashboard
   - 表单下方"没有账号？去注册"链接 → `/register`
3. 实现 `pages/Register/index.tsx`：邮箱+姓名+密码+确认密码（一致性校验），成功后 message 提示并跳登录页。
4. `App.tsx` 挂 `/register` 路由。

**验收**：注册→登录→进入 Dashboard 全流程真实可用；错误密码有明确报错（后端 detail 透出）。

### P8.3 路由守卫重构（RequireAuth）

**目标**：消灭 24 处手写 `notLoggedIn` 检查。

**实施要点**：
1. 新建 `frontend/src/components/RequireAuth.tsx`：无 token → `<Navigate to="/login" state={{ from: location }} replace />`
2. `App.tsx` 中所有业务路由统一包裹
3. **删除各页面里的 `notLoggedIn` 判断、`useNavigate` 跳转逻辑**（Search/ReviewTasks/Datasets/Insights/Models/Issues/Alerts 七个页面 + Dashboard 检查），相关 `return notLoggedIn ? null :` 改为直接渲染
4. 守卫用 zustand 存用户信息（见 P8.6），没有用户信息时先 `getMe()` 拉取，401 则走登录

**验收**：全局搜索 `notLoggedIn` 在 `src/pages` 下无结果；未登录访问任意业务路由 → 登录页 → 登录后回到原页面。

### P8.4 401 拦截与 token 自动刷新

**目标**：token 过期不再裸失败。

**实施要点**：
1. `client.ts` 响应拦截器：
   - 收到 401 且**不是** refresh 请求本身 → 尝试用 refresh_token 调 `/api/auth/refresh` 换新 access_token
   - 刷新成功：更新 localStorage，**重放原请求**（保存 config，改 header 后重发）
   - 刷新失败（refresh 也过期）：`clearToken()`，跳 `/login`（带 message 提示"登录已过期"）
   - 并发 401 时只发一次 refresh（用共享 promise 锁）
2. 建议封装 `client.ts` 的 `getErrorMessage(e)` 工具函数，返回 `e.response?.data?.detail || e.message`，供各页面替换重复的 `(e as {...}).response...` 样板
3. 各页面 catch 块批量替换为 `getErrorMessage`（P8.6 顺带做）

**验收**：手动篡改 localStorage 的 access_token 后操作页面，请求自动恢复成功；篡改 refresh_token 后操作页面，2 秒内跳转登录页并提示。

### P8.5 404 页与全局 ErrorBoundary

**实施要点**：
1. 新建 `pages/NotFound/index.tsx`：antd `Result status="404"` + 返回首页按钮
2. `App.tsx` 加 `<Route path="*" element={<NotFoundPage />} />`
3. 新建 `components/ErrorBoundary.tsx`（class 组件，React 官方模式），包裹 `App` 根，渲染错误时显示 antd `Result status="error"` + 重试按钮

**验收**：访问 `/xyz` 显示 404 页；在任意页面抛渲染异常显示错误兜底页而非白屏。

### P8.6 用户中心与全局用户状态（zustand）

**实施要点**：
1. 新建 `frontend/src/store/auth.ts`（zustand）：`user / setUser / logout / fetchMe`
   - `logout()`：clearToken（含 refresh token）→ navigate /login
2. Header 用户下拉（在 AppLayout 中）：邮箱、角色 Tag（admin 紫/analyst 蓝/operator 绿）、`个人设置`、`退出登录`
3. 新建 `pages/Profile/index.tsx`：展示当前用户信息 + 修改 full_name 表单（调 `PUT /api/auth/me`）+ 挂 `/profile` 路由（不进侧边栏，从下拉进）
4. Header 通知铃铛（Badge）拉取未处理告警数：调 `GET /api/v1/alerts?status=active` 取 total，点击跳 `/alerts`（轮询 60s 一次即可，注意组件卸载清理）

**验收**：右上角显示当前登录人；退出登录回登录页且清干净 token；铃铛显示真实未处理告警数。

### P8 阶段验收总标准

新克隆用户视角：注册 → 登录 → 侧边栏导航浏览全部 8 页 → 登录过期自动续期/重登 → 全程无白屏、无死链接。`npm test && npm run typecheck` 全绿。
